## 宿題

- 取り組んだレベル：**発展**（応答時間とトークン数を計測し、複数のモデルと質問で比較する。無料枠のレート制限との関係を考察する）
- やったこと：

4 モデル × 3 質問 × 3 回の計 36 回を、同じ計測スクリプトで測った。実装は Claude Code に任せ、比較するモデル・質問・実験の範囲（429 を出すバースト実験はしない）は自分で決めた。

| 項目 | 内容 |
|---|---|
| モデル | `gemini-3.5-flash-lite`、`gemini-3.1-flash-lite`、`gemini-3.8-flash`、`gemma-4-31b-it` |
| 質問 | `short`：「LoRAとは何ですか？」 |
| | `false_premise`：「秋田大学の学生に伝わっている、ヒグマに関するジンクスはなんですか？」（前提が偽。実在するのはカモシカに関するジンクス） |
| | `long`：LoRA の仕組みを、全体像・低ランク分解などの技術的側面・メリットとデメリット・活用例まで、大学1年生向けの記事として詳しく説明させる質問 |
| 呼び出し | `generate_content_stream`（ストリーミング）。温度などは既定のまま |
| 順序 | 3 回 × 質問 × モデルの順に交互に回し、時間帯の偏りを減らした |

計測した値（1 呼び出しごとに JSONL へ記録）：

- `latency_s`：送信から最後のチャンクまで
- `ttft_s`：送信から最初の回答テキストまで（TTFT）
- `output_s`：`latency_s − ttft_s`
- `prompt_tokens` / `output_tokens` / `thinking_tokens`：`usage_metadata` の値
- `chunks`：回答テキストを含むチャンクごとの `[受信時刻, 文字数, 累積出力トークン数]`

API が返す最小単位はチャンク（今回は 1 チャンクあたり約 25 トークン）で、トークン 1 つごとの時刻は取れない。出力速度は `output_tokens / output_s`（最初のチャンク以降の区間）で求めた。思考（thinking）は回答テキストより前に行われるので、思考の時間は TTFT に含まれる。

### レート制限との関係

1. **429 は出なかった。** 同じモデルへの呼び出しを `60 / RPM + 1` 秒以上あけたうえ、バーストはしていない。そのため、制限との関係は「観測したエラー」と「計測値からの計算」で考察する。
2. **逐次に叩き続けたときの 1 分あたり回数（= 60 ÷ 総時間の中央値）と RPM の比較。**

   | モデル | 総時間（中央値） | 逐次の回数/分 | RPM |
   |---|---|---|---|
   | gemini-3.5-flash-lite | 4.0 秒 | 約 15 | 15 |
   | gemini-3.1-flash-lite | 7.3 秒 | 約 8 | 15 |
   | gemini-3.8-flash | 27.5 秒 | 約 2 | 5 |
   | gemma-4-31b-it | 76.3 秒 | 約 0.8 | 30 |

   応答の速いモデルほど RPM に近づく。3.5-flash-lite は 1 本のスクリプトで逐次に叩くだけで、ほぼ RPM の上限になる。README が言うとおり、1 つの質問で LLM を複数回呼ぶエージェントなら、並列にしなくても 429 に当たりうる。逆に、遅いモデルは応答の遅さが自然なレート制限になり、RPM は問題にならない。
3. **1 日の枠（RPD）を逐次に使い切るまでの時間**（RPD × 総時間の中央値。質問の混ざり方による粗い見積もり）。

   | モデル | RPD | 使い切るまで |
   |---|---|---|
   | gemini-3.5-flash-lite | 500 | 約 33 分 |
   | gemini-3.1-flash-lite | 500 | 約 61 分 |
   | gemini-3.8-flash | 20 | 約 9 分 |
   | gemma-4-31b-it | 14.4K | 1 日では使い切れない（逐次なら 1 日に約 1,100 回が上限） |

   gemini-3.8-flash は 20 回しかなく、今回の計測だけで大半を使う。Gemma は枠が大きいが、1 回が遅いので時間のほうが先に尽きる。
4. **枠は「回数」で数えられ、思考トークンは数えられていないように見える。** gemini-3.8-flash は 1 回あたり約 1,100 トークンを思考に使い、その分 TTFT が 20〜30 秒になった。一方 [使用量の画面](<images/スクリーンショット 2026-10-22 170106.png>)（計測の途中）と[全計測後の画面](images/run_done.png)の TPM は数十〜100 程度（終了後は 4 モデルとも 95〜102）で、1 回の出力（数百〜千トークン超）よりずっと小さく、1 組の質問の入力トークン合計（7 + 21 + 69 = 97）に近い。TPM は入力側だけを数えているように見える（推測）。つまり無料枠では、思考や長い出力は枠を消費せず、時間を消費する。
5. **失敗は 7 / 36 回（約 19%）で、すべてサーバー側のエラーだった。** `503`（高負荷）が gemini-3.8-flash で 3 回、gemini-3.1-flash-lite で 1 回、`500`（内部エラー）が gemma-4-31b-it で 3 回。レート制限（429）ではないが、無料枠のモデルは混雑すると失敗しやすい。失敗した呼び出しが 1 日の枠（RPD）に数えられるかは、使用量の画面から判断できなかった。全計測後の [画面](images/run_done.png) の RPD は、gemini-3.1-flash-lite が 8（成功 8 回と一致）、gemini-3.8-flash と gemma-4-31b-it が 7（成功 6 回 + 1）だった。失敗はほぼ数えられていないように見えるが、gemini-3.5-flash-lite は 8 で、送った 12 回（計測 9 回 + 動作確認 3 回）より少なく、画面の集計の遅れか集計期間の違いがありそうで、辻褄が合わない。

- 気づき・疑問：

- **TTFT と総時間の順位は一致しない。** 3.5-flash-lite は TTFT が 0.6 秒で、3.1-flash-lite の 4.2 秒より速い。しかし `long` では 3.5 が約 1,700 トークンと長く書くため、総時間は 8.3 秒と 7.6 秒でほぼ同じになる。「速いモデル」は、TTFT と総時間のどちらで見るかで変わる。
- **思考するモデルは TTFT が長い。** gemini-3.8-flash は `short` でも 20〜55 秒かかり、`false_premise` では思考トークン（1,333）が出力（204）の 6 倍以上だった。gemma-4-31b-it は思考が約 680 トークンで、出力も 37 トークン/秒と遅く、総時間が最大 105 秒になった。
- **同じ質問でもばらつきが大きい。** gemini-3.1-flash-lite の `false_premise` は 4.5 秒、6.1 秒、42.3 秒、gemini-3.8-flash の `short` は 20.1〜55.6 秒だった。3 回では少なく、平均より中央値を見るべきだが、中央値も n = 3 では頼りない。
- **`short` の質問でも出力は 500〜800 トークンになる。** 「LoRAとは何ですか？」だけだと、どのモデルも長く答える。質問に「一文で」などの制約を足さないと、出力長のばらつきが応答時間にそのまま出る。入力トークン数は、同じ質問ならモデルによらず同じだった（7 / 21 / 69）。
- **前提が偽の質問への強さは、モデルの大きさや新しさでは決まらなかった。** 最新の gemini-3.8-flash が一番自信満々に作り話をし、軽い gemini-3.1-flash-lite と gemma は断った。同じ flash-lite でも 3.5 は作り話を足し、3.1 は断った。ただし各 2〜3 回で、断った回答の中にも未確認の記述がある（例：gemma は「農学部など」と書いたが、秋田大学にその学部があるかは未確認）。回答の内容は正誤を詳しく検証していない。
- **疑問：** gemini-3.8-flash の `long` では、約 2,000 トークンが 1.3 秒で届き、出力速度が約 1,500 トークン/秒になった（成功は 1 回だけ）。`short` と `false_premise` では約 100 トークン/秒なので一貫しない。サーバー側でまとめて返した可能性があるが、確かめていない。上の表の gemini-3.8-flash の tokens/s（平均 339）は、この 1 回に引っ張られている。
- **限界：** 各条件 3 回までで、失敗した呼び出しを除くと 1〜3 回になる条件がある。1 日の中の 1 回の実行であり、時間帯による混雑の違いは見ていない。429 を意図的に出す実験はしていないため、制限を超えたときの挙動（待ち時間の指示など）は確認していない。
