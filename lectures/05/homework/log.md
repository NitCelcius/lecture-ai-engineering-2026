### 評価：表記の組ごとのラベル

全実行で出た組を合わせて247組。Claude が下書きのラベルを付け、ユーザーが確認した（y 43組）。`term_pairs.csv`。

- precision = 出した組のうち y の割合。recall = y 43組のうち出せた割合。
- accuracy は使わない。783語から作れる組は約30万組で、ほぼすべてが負例のため。
- recall の分母は「どれかの実行で出た y」に限られる。どの実行も出さなかった組は数えられないので、recall は高めに出る。

- A（まとめて）は precision が上がり recall が下がった。C（reason なし）は plain とほぼ変わらず、ばらつきが大きい。
- どの条件も実行ごとのばらつきが大きい（B でも F1 0.53〜0.76）。3回ずつでは条件の差とばらつきを分けきれない。

### 採用したプロンプトと多数決

- B（言い換え）を `scripts/group_terms.py` に採用した。1回だけの実行は P 0.90 / R 0.21 / F1 0.34 と、B の平均（0.63）を大きく下回った。
- そこで3回実行し、過半数（2回以上）で同じグループに入った表記の組だけを残すようにした（`--runs 3`）。結果は10グループで、P 0.80 / R 0.47 / F1 0.59。
- 誤りの1つは、MCP のグループに MCP Server / MCP サーバーが入ったこと。組をつないでグループを作るので、1組の誤りでグループ全体が広がる。
